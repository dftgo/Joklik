# תוכנית – Milestone 5: בדיקת גרסה מלאה ב-Production

## מטרה
לוודא שהמוצר המלא עובד בסביבה החיה ב-Vercel: יצירת בדיחות, העתקה, שיתוף, שגיאות, RTL, התקנת PWA באנדרואיד ובאייפון, והגנות האבטחה והעלויות (API Key, Rate Limiting, תקרת הוצאה). לתקן כל ממצא שעולה.

זה Milestone של **בדיקות**, לא של פיצ'רים חדשים. קוד משתנה רק אם בדיקה נכשלת.

## נקודת המוצא (מצב הקוד היום)
- Milestones 1–4 אושרו ונדחפו ל-`main`; Vercel מחובר ומבצע Deployment אוטומטי (ADR-4). הגרסה החיה היום = הקוד הנוכחי.
- Manifest ב-`app/manifest.ts` (שם, שם קצר, `lang`/`dir`, `standalone`, צבעים, אייקונים 192/512/maskable); `apple-touch-icon` ב-`app/layout.tsx`; אייקונים סופיים ב-`public/icons/`.
- Service Worker ב-`public/sw.js` ללא cache (ADR-5), נרשם ב-`components/ServiceWorkerRegister.tsx`; `next.config.ts` מונע cache של `sw.js`.
- ה-Backend (`app/api/joke/route.ts` + `lib/joke.ts`) קורא ל-OpenAI עם `store: false`, `maxRetries: 0`, timeout 25 שניות. ה-log היחיד הוא קוד שגיאה וזמן (בלי תוכן) — תואם ARCHITECTURE 2.4.
- ה-Frontend ממפה 429 ל„רגע, לאט לאט...“, וכל קוד אחר (כולל 403) ל„משהו השתבש“.

## גבולות ה-Milestone (מה **לא** נבנה)
- אין פיצ'רים, מסכים, טקסטים או רכיבי עיצוב חדשים.
- אין כפתור התקנה, אין cache/Offline, אין Database, אין Analytics או ניטור חיצוני.
- אין שינוי בהגדרות Vercel/OpenAI על ידי Claude — בעל הפרויקט מבצע אותן בעצמו, בהדרכה צעד אחר צעד.
- אין push בלי אישור מפורש (כל push מעדכן מיד את האתר החי).

## נקודת החלטה צפויה: פעולת כלל ה-Rate Limiting
ב-Milestone 2 הוגדר שאם תוכנית Hobby לא מאפשרת פעולת `429`, בוחרים `Deny`. `Deny` מחזיר **403**, ולכן המשתמש יראה „משהו השתבש“ ולא „רגע, לאט לאט...“ — וזה לא עומד בתנאי ה-DoD („חסימת Rate Limiting… מציגה את ההודעה המתאימה“).
- בשלב 2 בודקים איזו פעולה הוגדרה בפועל.
- אם `429` — אין בעיה.
- אם `Deny` — **עוצרים ושואלים את בעל הפרויקט** (לא מחליטים לבד). אפשרויות להציג בפשטות:
  1. לשנות את הכלל לפעולת `429` (אם התוכנית מאפשרת, או בשדרוג ל-Pro).
  2. להשאיר `Deny` ולקבל „משהו השתבש“ בחסימה — מחייב עדכון PRD/ARCHITECTURE באישור.
  3. למפות 403 מ-`/api/joke` ל„רגע, לאט לאט...“ בקוד — הקוד שלנו לא מחזיר 403 אף פעם, אבל זה משנה את טבלת המיפוי ב-ARCHITECTURE 2.9, ולכן גם כאן נדרש אישור.

## שלבי העבודה

### שלב 1 – בדיקות מקומיות שלא דורשות את בעל הפרויקט (Claude)
1. `npm run build` עובר בלי שגיאות.
2. **סריקת סודות בקוד וב-Git:**
   - חיפוש מחרוזות שנראות כמו מפתח (`sk-`) בכל הקבצים שב-Git ובכל היסטוריית ה-commits (`git log -p`), בלי לפתוח את `.env`.
   - וידוא ש-`.env` מוחרג ב-`.gitignore` ואינו מופיע ב-`git ls-files`.
   - וידוא שאין משתנה עם קידומת `NEXT_PUBLIC_` בקוד.
   - חיפוש `OPENAI` ו-`sk-` בתוצרי ה-Build של הדפדפן (`.next/static`).
3. בדיקת הכתובת החיה מהמחשב (בדפדפן המובנה), ללא יצירת בדיחות רבות:
   - הכתובת נפתחת ב-HTTPS, והפניה מ-`http://` ל-`https://`.
   - `/manifest.webmanifest` נטען ותקין (שם, שם קצר, `standalone`, `lang`/`dir`, אייקונים); כל קובצי האייקון וה-`apple-touch-icon` מחזירים 200.
   - `/sw.js` נטען עם `Cache-Control: no-cache, no-store`, וה-Service Worker רשום ופעיל.
   - אין שגיאות ב-Console.
   - יצירת בדיחה אחת: בקשת הרשת היחידה היא ל-`/api/joke` באותו דומיין; אין בקשה ל-`openai.com` ואין מפתח בבקשה או בתשובה.
   - RTL: `lang="he"`, `dir="rtl"`, שדה מיושר לימין (ב-Mobile viewport 375×812).
4. רשימת ממצאים — כל כשל עובר לשלב 5.

### שלב 2 – הדרכת בעל הפרויקט: הגדרות בדשבורדים
הדרכה צעד אחר צעד, בשפה פשוטה; בעל הפרויקט מדווח מה רואה.
1. **Vercel → Project → Settings → Environment Variables:** `OPENAI_API_KEY` קיים, מסומן Sensitive (הערך מוסתר ולא ניתן לצפייה), ומוגדר ל-Production. `OPENAI_MODEL=gpt-6-luna`. אין משתנים מיותרים עם המפתח.
2. **Vercel → Project → Settings → Git:** Production Branch הוא `main` (Deployment אוטומטי). ב-Deployments — ה-Deployment האחרון נוצר מה-commit של Milestone 4.
3. **Vercel → Firewall:** כלל Rate Limiting קיים ופעיל על `/api/joke`, 10 בקשות/דקה ל-IP, Fixed Window — ומה הפעולה (`429` / `Deny`). ← ראה „נקודת החלטה צפויה“.
4. **OpenAI → Project של האפליקציה → Limits/Billing:** תקרת הוצאה חודשית מוגדרת (בעל הפרויקט מאשר שהיא קיימת; הסכום לא נדרש).
5. תוצאה: רשימת ✔/✘ לכל סעיף. ✘ מתוקן על ידי בעל הפרויקט בהדרכה.

### שלב 3 – בדיקות בטלפון אמיתי (בעל הפרויקט, עם צ'קליסט מ-Claude)
Claude מכין צ'קליסט קצר בעברית; בעל הפרויקט מבצע ומדווח.

**בדפדפן (לפני התקנה), באנדרואיד (Chrome) ובאייפון (Safari):**
- נושא בעברית → בדיחה בנושא, בעברית, עד 10 שורות.
- שדה ריק → בדיחה כללית.
- מצב טעינה „מכין לך בדיחה...“ מוצג; אי אפשר ללחוץ שוב בזמן הטעינה.
- „העתק“ → „הועתק!“, והדבקה באפליקציה אחרת עובדת.
- „שתף“ → נפתח חלון השיתוף; סגירה בלי לשתף לא מציגה שגיאה.
- RTL: כל הטקסטים מימין לשמאל, אין עברית הפוכה, השדה מיושר לימין, המקלדת וההקלדה תקינות; לא ניתן להקליד מעל 100 תווים.

**שגיאות בסביבה החיה:**
- **אין חיבור:** פותחים את האפליקציה, מעבירים למצב טיסה, לוחצים „צור בדיחה“ → „אין חיבור לאינטרנט“; מחזירים חיבור → „נסה שוב“ מביא בדיחה עם הנושא שבשדה.
- **סירוב תוכן:** נושא שאי אפשר להצחיק עליו לכל המשפחה → „לא הצלחנו להצחיק על זה“ (תלוי בתשובת המודל; אם לא מתקבל אחרי 2–3 ניסיונות — מתועד, ומצב זה כבר נבדק מקומית ב-Milestone 3).
- **Rate Limiting:** לוחצים „צור בדיחה“ 11 פעמים ברצף בתוך דקה → הבקשה ה-11 נחסמת ומוצגת ההודעה המתאימה; אחרי דקה — חוזר לעבוד. (עולה כ-10 בקשות — שבריר סנט.)
- **שגיאה כללית:** לא מאולצת בייצור (אין דרך בטוחה לעשות זאת בלי לשנות הגדרות); נבדקה ב-Milestone 3, ומכוסה בחלקה כשהחסימה היא 403.

**התקנת PWA:**
- **אנדרואיד:** Chrome → תפריט ⋮ → „התקנת אפליקציה“/„הוספה למסך הבית“ → האייקון הסופי והשם „מחולל בדיחות“ במסך הבית; נפתחת במסך מלא בלי שורת כתובת.
- **אייפון:** Safari → שיתוף → „הוסף למסך הבית“ → האייקון והשם „מחולל בדיחות“; נפתחת בלי שורת כתובת.
- בשניהם, באפליקציה המותקנת: יצירת בדיחה, העתקה ושיתוף עובדים.
- **פתיחה מחדש ו-reload:** סגירה מלאה של האפליקציה המותקנת ופתיחה מחדש → המסך הראשוני נקי (בלי הבדיחה הקודמת — אין שמירה). באנדרואיד גם משיכה למטה/רענון. אחרי פתיחה מחדש יצירת בדיחה עדיין עובדת.

### שלב 4 – בדיקת הדרישות המרכזיות של ה-PRD מקצה לקצה
טבלה אחת (בתשובה הסופית ל-Milestone) שעוברת על הדרישות של PRD סעיפים 3–5 ומסמנת לכל אחת: נבדק היכן (מקומי / Production / טלפון) ותוצאה. כולל: אין הרשמה/התחברות, אין Database, אין היסטוריה (רענון מאפס, אין Local Storage עם תוכן), אין כפתור התקנה בממשק, אין רכיבים מרשימת Out of Scope.

### שלב 5 – תיקון ממצאים
- תיקון בקוד → `npm run build` → בדיקה מקומית → בדיקה של Claude בדפדפן המובנה.
- כדי שהתיקון יגיע ל-Production צריך push — **עוצרים ומבקשים אישור** לפני כל push (לפי CLAUDE.md). אחרי ה-push בודקים שוב בכתובת החיה את מה שתוקן.
- תיקון שמשנה התנהגות שמתוארת ב-spec — מדווחים לבעל הפרויקט, שמחליט אם לעדכן את המסמך.
- הגדרה בדשבורד שגויה — בעל הפרויקט מתקן בהדרכה.
