# MILESTONES – מחולל בדיחות AI

## Development Execution Rules

יש לפתח את ה-Milestones לפי הסדר המוגדר במסמך זה.

לאחר השלמת כל Milestone:
1. יש לעצור את הפיתוח.
2. יש להציג למשתמש מה הושלם בפועל.
3. יש להציג את תוצאות הבדיקות מול ה-Definition of Done של אותו Milestone.
4. אין להתחיל בפיתוח ה-Milestone הבא ללא אישור מפורש של המשתמש.

---

## Milestone 1 – הקמת שלד האפליקציה ו-PWA בסיסי

### שם ומטרה
להקים את בסיס הפרויקט כך שהאפליקציה תעלה מקומית, תהיה מותאמת למובייל, תעבוד ב-RTL ותהיה מוכנה להתקנה כ-PWA.

### מה יש לממש
- יצירת פרויקט Next.js עם TypeScript.
- הגדרת מבנה בסיסי של Frontend ו-Backend בתוך אותו פרויקט.
- הגדרת `dir="rtl"` ושפת ממשק עברית.
- הוספת PWA manifest.
- הגדרת אייקונים בסיסיים ל-PWA.
- הגדרת metadata בסיסי לאפליקציה.
- יצירת המסך הראשי בהתאם למבנה שהוגדר ב-DESIGN.md.
- יצירת רכיבי UI ראשוניים:
  - Header.
  - שדה הזנת נושא.
  - כפתור **„צור בדיחה“**.
  - אזור תוצאה.
  - כפתורי **„העתק“** ו-**„שתף“** במצב לא פעיל כל עוד אין תוצאה.
- התאמת ה-Layout למסכי Mobile.

### תוצר מצופה
אפליקציה שניתן להריץ מקומית, המציגה את מסך יצירת הבדיחה בעיצוב בסיסי, בעברית וב-RTL, וניתנת לזיהוי כ-PWA.

### Definition of Done
- האפליקציה עולה ללא שגיאות.
- המסך הראשי מוצג במכשיר Mobile או ב-Mobile viewport.
- כל הטקסטים בעברית מוצגים בכיוון תקין מימין לשמאל.
- שדה הקלט וכפתור **„צור בדיחה“** מוצגים לפי מבנה ה-Design.
- קיימים manifest ואייקונים תקינים ל-PWA.
- אין Database.
- אין Authentication.
- אין API Key ב-Frontend.
- אין קריאה ל-OpenAI עדיין.
- המשתמש יכול לבדוק ידנית את המסך ואת RTL לפני מעבר לשלב הבא.

## Milestone 2 – יצירת בדיחה מקצה לקצה דרך Backend

### שם ומטרה
לממש את היכולת המרכזית של המוצר: המשתמש מזין נושא, האפליקציה שולחת את הבקשה ל-Backend, וה-Backend מחזיר בדיחה שנוצרה באמצעות GPT-5.

### מה יש לממש
- יצירת Backend endpoint בתוך Next.js.
- חיבור OpenAI API בצד ה-Backend בלבד.
- שמירת `OPENAI_API_KEY` כ-Environment Variable בצד השרת.
- הגדרת `OPENAI_MODEL` כ-Configuration, עם `gpt-5` כברירת מחדל.
- קבלת `topic` מה-Frontend.
- אם `topic` ריק:
  - יצירת בדיחה כללית.
- אם `topic` אינו ריק:
  - יצירת בדיחה הקשורה לנושא שהוזן.
- הנחיית המודל להחזיר בדיחה באורך של עד 10 שורות.
- הצגת מצב טעינה בזמן יצירת הבדיחה.
- הצגת התוצאה באותו מסך.
- החלפת תוצאה קודמת כאשר נוצרת בדיחה חדשה.
- מניעת שליחה כפולה בזמן שבקשה קיימת עדיין בטיפול.

### תוצר מצופה
המשתמש יכול להזין נושא וללחוץ על **„צור בדיחה“**, לראות מצב טעינה ולקבל בדיחה באותו מסך.

### Definition of Done
- בקשה עם נושא מחזירה בדיחה הקשורה לנושא.
- בקשה עם שדה ריק מחזירה בדיחה כללית.
- הבדיחה מוצגת באותו מסך.
- מוצג מצב **„מכין לך בדיחה...“** בזמן ההמתנה.
- לא ניתן ליצור בקשות כפולות לא מכוונות בזמן טעינה.
- ה-API Key אינו מופיע ב-Browser bundle, בקוד Client או ב-Network request ל-OpenAI.
- הקריאה ל-OpenAI מתבצעת מה-Backend בלבד.
- אורך התוצאה בפועל מוגבל בהתאם לדרישה של עד 10 שורות.
- נבדקו לפחות:
  - נושא בעברית.
  - נושא באנגלית.
  - שדה ריק.
- המשתמש יכול לבדוק את הזרימה מקצה לקצה לפני מעבר לשלב הבא.

## Milestone 3 – העתקה, שיתוף וטיפול בשגיאות

### שם ומטרה
להשלים את זרימת השימוש המרכזית באמצעות פעולות על הבדיחה וטיפול ברור במקרי תקלה.

### מה יש לממש
- כפתור **„העתק“**:
  - העתקת טקסט הבדיחה ל-Clipboard.
- כפתור **„שתף“**:
  - שימוש ב-Web Share API כאשר הוא נתמך.
- Fallback מתאים כאשר Share API אינו זמין, ללא הוספת פיצ'ר חדש מעבר ליכולת השיתוף שהוגדרה.
- Error State עבור:
  - שגיאת רשת.
  - שגיאת Backend.
  - שגיאת OpenAI.
  - תשובה לא תקינה.
- הצגת הודעה כגון:
  - **„משהו השתבש, נסה שוב“**
- הוספת כפתור:
  - **„נסה שוב“**
- שמירת הנושא שהוזן לצורך Retry של אותה בקשה בתוך ה-State של המסך בלבד.
- אין שמירה קבועה של נתונים.

### תוצר מצופה
לאחר יצירת בדיחה, המשתמש יכול להעתיק או לשתף אותה. במקרה של תקלה, הוא מקבל הודעה ברורה ויכול לנסות שוב.

### Definition of Done
- כפתור **„העתק“** מעתיק את הבדיחה בפועל.
- כפתור **„שתף“** פותח את מנגנון השיתוף של המכשיר בדפדפן נתמך.
- שגיאת רשת מציגה Error State.
- שגיאת OpenAI מציגה Error State.
- לחיצה על **„נסה שוב“** מבצעת ניסיון נוסף.
- אין קריסה או מסך ריק במצב שגיאה.
- לא נשמרת היסטוריה.
- לא נשמרות בדיחות.
- אין שימוש ב-Database או Local Storage לצורך שמירת התוכן.
- כל הטקסטים במצבי שגיאה ופעולה מוצגים בעברית וב-RTL.

## Milestone 4 – השלמת העיצוב בהתאם ל-Design System

### שם ומטרה
להביא את הממשק לרמת העיצוב הסופית בהתאם ל-DESIGN.md, ל-Style Guide ול-Mockups.

### מה יש לממש
- יישום מלא של Color Palette.
- שימוש בטיפוגרפיה שהוגדרה.
- יישום spacing עקבי.
- יישום Cards, Borders, Shadows ו-Radius בהתאם לעיצוב.
- התאמת Primary CTA ו-Secondary Actions.
- שילוב האלמנטים הדקורטיביים שאושרו:
  - ספארי.
  - גווני קרם וחול.
  - ירוקים.
  - כחולים רכים.
  - איורים בסגנון ידידותי / watercolor.
- בדיקה שכל אלמנט דקורטיבי אינו פוגע בקריאות או בשימושיות.
- התאמת כל מצבי המסך:
  - Initial.
  - Loading.
  - Result.
  - Error.
- בדיקת RTL מלאה גם ברכיבים אינטראקטיביים.

### תוצר מצופה
אפליקציה שנראית ומתנהגת בהתאם ל-Design המאושר ולא רק כגרסה פונקציונלית.

### Definition of Done
- המבנה תואם ל-Wireframe.
- השפה החזותית תואמת ל-Style Guide.
- התוצאה תואמת למראה של ה-Mockup המאושר.
- כל הטקסטים בעברית מוצגים RTL תקין.
- אין טקסט עברי הפוך.
- שדה הקלט מיושר לימין.
- כל מצבי המסך מעוצבים באופן עקבי.
- אין רכיבי UI או פיצ'רים שלא הוגדרו במסמכי הפרויקט.
- העיצוב נבדק ב-Mobile viewport ריאלי.

## Milestone 5 – PWA, Production Deployment ובדיקת גרסה מלאה

### שם ומטרה
לפרוס את האפליקציה ל-Production ב-Vercel, לחבר אותה ל-GitHub, לוודא שה-PWA ניתנת להתקנה ולבדוק את המוצר המלא בסביבה החיה.

### מה יש לממש
- יצירת Git Repository ב-GitHub אם טרם נוצר.
- חיבור ה-Repository ל-Vercel.
- הגדרת Deployment אוטומטי מ-GitHub.
- הגדרת Environment Variables ב-Vercel:
  - `OPENAI_API_KEY`
  - `OPENAI_MODEL`
- וידוא שפרטי Production אינם נשמרים בקוד.
- בדיקת PWA ב-Production.
- בדיקת התקנה למכשיר נתמך.
- בדיקת HTTPS.
- בדיקת יצירת בדיחה בסביבה החיה.
- בדיקת Clipboard.
- בדיקת Share.
- בדיקת Error State.
- בדיקת RTL במכשיר Mobile אמיתי או Browser Mobile Mode.
- בדיקת reload ופתיחה מחדש של האפליקציה.
- וידוא שאין תלות ב-Database.

### תוצר מצופה
גרסת Production פעילה, נגישה דרך URL מאובטח, מחוברת ל-GitHub, עם Deployment אוטומטי ו-PWA שניתן להתקין.

### Definition of Done
- האפליקציה זמינה ב-URL של Production.
- כל Push ל-Branch המוגדר מפעיל Deployment אוטומטי.
- `OPENAI_API_KEY` קיים רק ב-Vercel Environment Variables ובסביבת הפיתוח המקומית המאובטחת.
- האפליקציה יוצרת בדיחות דרך ה-Backend בסביבת Production.
- PWA installability נבדקה.
- RTL נבדק ב-Production.
- Share ו-Copy עובדים במכשיר נתמך.
- Error State עובד בסביבת Production.
- לא קיים Database.
- לא קיימת הרשמה או התחברות.
- לא נשמרת היסטוריה.
- כל הדרישות המרכזיות ב-PRD נבדקו מקצה לקצה.

---

## סיכום סדר הפיתוח

1. הקמת שלד האפליקציה ו-PWA בסיסי.
2. יצירת בדיחה מקצה לקצה דרך Backend ו-GPT-5.
3. העתקה, שיתוף וטיפול בשגיאות.
4. השלמת העיצוב וה-RTL.
5. Deployment ל-Production ובדיקת הגרסה המלאה.

יש לעצור לאחר כל Milestone ולקבל אישור מפורש מהמשתמש לפני המשך הפיתוח.
